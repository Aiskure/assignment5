## 三、高频面试问题 & 回答

### Q1: 能解释一下 GRPO 是什么吗？和 PPO / RLHF 有什么区别？

**回答要点**：
- GRPO（Group Relative Policy Optimization）是 DeepSeek 提出的，核心思想是**不需要 value model**
- 传统 RLHF 用 PPO，需要一个 critic/value network 来估计 baseline（advantage = reward - value）。GRPO 的做法是对同一个 prompt 生成一组（比如 8 个）response，用组内均值作为 baseline，组内标准差做归一化
- 好处：省掉了 value model 的显存和训练开销，对小模型特别友好
- 和 PPO 的另一个共同点：都有 clipped surrogate objective 来控制更新步长

### Q2: 什么是 entropy collapse？你怎么发现和解决的？

**回答要点**：
- Entropy collapse 是指 policy 的输出分布变得极度集中（entropy → 0），模型只会输出固定的几个 token
- 我在 run7 发现的：训练过程中 1024 条验证子集的 accuracy 一直在涨（peak 39.8%），看起来一切正常。但训练结束后用全量 5000 条评估，accuracy 是 **0%**——模型已经退化到只输出重复的 emoji
- 根本原因：off-policy 训练（多 epoch 复用同一批 rollout）时，policy 和 rollout distribution 偏离太远，没有机制约束
- 解决方案：加 KL penalty（KL(π_θ || π_ref)），用冻结的初始模型作为 reference。很小的系数（kl_coef=3e-4）就够了
- 教训：小 eval 子集会给你虚假的安全感，entropy 监控 + 全量评估很重要

### Q3: masked_normalize 和 masked_mean 有什么区别？为什么前者更好？

**回答要点**：
- masked_mean：loss 除以实际 response token 数（每条 response 的有效 token 数）
- masked_normalize：loss 除以 max_gen_len（所有 response 共用同一个常数做归一化）
- 效果差距：+10.4 个百分点
- 原因分析：masked_mean 对所有 response "一视同仁"（per-token loss 相同权重），但 masked_normalize 让长 response 贡献更多梯度。由于正确的数学推理往往需要更长的 chain-of-thought，这相当于隐式地给"正确且完整的推理"更大的权重
- 这个发现说明 loss 的归一化方式是一个容易被忽视但影响很大的超参

### Q4: 你怎么处理 off-policy 训练的数值稳定性问题？

**回答要点**：
- 问题：GRPO-clip 的 ratio = exp(log_π_θ - log_π_old)。当 policy 偏离 rollout policy 太远时，log ratio 可以变得很大，exp 后变成 inf，导致 gradient norm 达到 10¹³
- 解决：在 exp() 之前对 log ratio 做 clamp(-20, 20)，一行代码解决
- 这是 off-policy RL 的经典问题：importance sampling ratio 的方差随 policy 偏离程度指数增长
- 更根本的解决是加 KL penalty 防止 policy 偏离太远（和 Q2 关联）

### Q5: 你的消融实验是怎么设计的？

**回答要点**：
- 采用控制变量法，每次只改一个因素：
  1. **LR sweep**（5 个值：3e-6, 1e-5, 1.5e-5, 2e-5, 3e-5）→ 确定 sweet spot 1.5e-5
  2. **Loss type**（no_baseline vs reinforce_with_baseline vs grpo_clip）→ 确认 baseline 必要性
  3. **Advantage normalization**（use_std=True vs False）→ 确认标准差归一化有帮助
  4. **Loss aggregation**（masked_mean vs masked_normalize）→ 发现关键提升
  5. **KL coefficient sweep**（0, 3e-4, 1e-3, 3e-3）→ 确定最小有效值
  6. **Group filtering**（跳过全对/全错组 vs 不跳过）
- 每组实验都跑完整 256 步并记录完整训练曲线，不是只看最终结果
- 这样做的好处是能观察到训练动态（比如 3e-5 学习率在 step 100 peak 36% 后 entropy collapse）

### Q6: 为什么不用 SFT 后再做 GRPO？

**回答要点**：
- 试过了，效果反而更差。原因是模型太小（1.5B）
- SFT 后模型的 output distribution 已经变窄了（学会了特定的回答模式），GRPO 需要探索空间来发现更好的策略
- 从 base model 直接做 GRPO，模型有更大的 entropy（探索空间），可以通过 RL 自己找到更好的推理路径
- 这和 DeepSeek-R1 的发现一致：他们也是直接在 base model 上做 RL

### Q7: Expert Iteration 和 GRPO 有什么区别？为什么 GRPO 效果好很多？

**回答要点**：
- Expert Iteration (EI) = rejection sampling + SFT：生成多个回答，只保留正确的，然后做监督学习
- GRPO = online RL：直接用 policy gradient 优化，advantage 来自组内比较
- EI 的问题：只用了"对/错"的二值信号，丢弃了错误样本中的信息；而且 SFT 步骤相当于 behavior cloning，没有鼓励探索
- GRPO 的优势：利用了组内排序信息（不只是对错，还有谁比谁好），而且 RL 的优化目标直接最大化 reward
- 结果对比：EI 最优 21.9% vs GRPO 最优 46.05%

### Q8: 你用了什么技术栈？训练环境怎样？

**回答要点**：
- PyTorch 原生实现训练循环（不是用 HuggingFace Trainer 或 TRL）
- vLLM 做推理加速（rollout 生成和评估）
- Transformers 加载模型和 tokenizer
- W&B 做实验追踪（offline 模式，集群网络限制）
- 4× A100 40GB（NSCC 新加坡超算中心），单卡训练 + 多卡 vLLM 推理
- flash-attn 加速注意力计算

### Q9: 如果给你更多时间和资源，你会做什么改进？

**回答要点**：
- **模型规模**：在更大的模型（7B/14B）上验证这些发现是否 scale
- **Online GRPO**：当前实现是 off-policy（复用 rollout），online 每步重新采样可能效果更好但更慢
- **Process Reward Model (PRM)**：当前用 outcome reward（最终答案对/错），PRM 可以给中间推理步骤打分
- **更好的 KL 控制**：目前用固定 kl_coef，可以尝试 adaptive KL（根据 KL 距离自动调整系数）
- **数据质量**：当前 MATH 数据集质量参差，可以做数据清洗或 curriculum learning

### Q10: 这个项目你遇到的最大挑战是什么？

**回答要点**：
- **Entropy collapse 的隐蔽性**。训练曲线看起来一切正常（在 1024 条子集上 accuracy 持续上升），但实际上模型已经崩溃了。这让我意识到：
  1. 评估子集太小会给出误导性结论
  2. 需要监控更多指标（entropy, KL divergence），不能只看 accuracy
  3. Off-policy RL 的稳定性不能想当然，需要显式的约束机制

## 四、可能的深挖问题（进阶）

这些问题面试官不一定会问，但如果问到说明他们想考察你的深度。

### GRPO 的梯度推导？
- ∇J = E[∇log π(a|s) · A(s,a)]
- GRPO 里 A(s,a) = (r_i - mean(r)) / std(r)，组内计算
- clip 版本：min(ratio · A, clip(ratio, 1-ε, 1+ε) · A)

### 为什么用 group 内的 std 做归一化？
- 控制 advantage 的 scale，防止不同 batch 的梯度量级差异过大
- 消融实验验证过：use_std=True 比 False 好 ~8pp（run7 vs run8）

### KL penalty 具体怎么算的？
- KL(π_θ || π_ref) = Σ_t [log π_θ(a_t|s_t) - log π_ref(a_t|s_t)]
- 只在 response token 上算（mask 掉 prompt 和 padding）
- 用 "low variance" 估计：直接在 log space 算差值，不需要采样

### Off-policy 和 on-policy 在你的实现里具体区别是什么？
- On-policy (epochs=1)：每次 rollout 只训练一个 epoch，ratio ≈ 1，clip 几乎不起作用
- Off-policy (epochs>1)：复用同一批 rollout 训练多个 epoch，policy 和 rollout policy 逐渐偏离，此时 clip 和 KL 才真正发挥作用
- 我发现 epochs=2 + KL 是最优组合：充分利用每批 rollout 数据，同时防止偏离过远

### 怎么理解 "clipped surrogate objective"？
- 不 clip：ratio 可以无限大，一个高 advantage 的样本可以让 policy 剧烈变化
- clip 到 [1-ε, 1+ε]：限制单步更新的幅度，相当于在 policy space 里做 trust region
- 和 PPO 的 clip 完全一样的思想

4. **承认不足**：如果被问到不会的，可以说"这个我没深入研究过，但我的理解是..."
5. **关联到岗位需求**：如果是 LLM 岗位，强调你对训练稳定性、超参调优、RL for LLM 的实践经验
